# Scoped HTTP reverse requests and response loans

This slice adds legacy HTTP reverse requests to the shared runtime and is now integrated at `1284440`. It preserves Roots, Sampling, ping and legacy elicitation in Arbor.MCP 2.x for their pinned protocol revisions. Modern MRTR uses the retained `Server.elicit/1` descriptor; the additive `Server.elicit(server, params, timeout \\ 5_000)` exports `/2` and `/3` for a side-effecting legacy request. A finite positive timeout only shortens the original callback cutoff. Form/URL parameters use the pinned 2026-07-28 `ElicitRequestParams` schema and its 12 transitive definitions, with the existing bounded SchemaPolicy backend and native plain-JSON gate. The validator performs no network resolution, custom encoding, casts, default insertion or arbitrary Inspect callbacks. The constructor retains the existing elicitation aliases and generated URL-mode ID policy.

An HTTP callback must be the actual protected Scheduler Task for its current source token, phase, cohort, runtime, exact session lease and server-derived private endpoint. An exact live legacy GET is required at producer-side durable-request admission. Already accepted append effects can survive GET retirement while original source and lease authority remain live; they are not byte receipts and cannot be retried. Modern reverse requests remain unavailable. Pending-ID inspection is restricted to that source's exact session/endpoint, or its own sessionless scope.

Outgoing controls use the existing outgoing control lane. A known unread phase 3 retirement frees the pending control even when its original callback Task remains alive; entered phase 1 retains its actual ACK/DOWN liability. Incoming responses use the existing incoming lane. The actual socket publishes a detached precharged ETS candidate; Gateway and Admission exchange only tokens and a 32-byte digest. Admission validates installed Gateway, protected actual producer metadata, original binding/socket/lease/generation/cutoff, and the complete candidate digest before adopting a result. A protected Admission index and fixed adopted witness inside the original incoming ByteBudget claim authenticate checkout. The result body never enters the callback mailbox. Only its actual original Task can check it out and acknowledge its fixed local receipt.

A checked-out result holds its original incoming count/byte credits through deadline expiration or generation reset until actual Task ACK/DOWN. Admission loss reconstructs only that finite liability from the held byte/slot claim; unread phase 0 values are discarded, and entered data is never restored for another checkout. No application dictionary is copied or queried remotely. Missing or replaced result backing cannot refund an authentic live consumer. This is a per-runtime ownership guarantee; independent replacement Roots have independent domains. Existing owned callback termination and the runtime's full lifecycle remain separate gates.

Each response member holds an incoming work permit. Each ordinary request, notification or invalid element holds a normal work permit. A frame's body bytes are charged once per admitted lane envelope; mixed arrays retain independently charged response-prefix and normal envelopes, not copies per member. The incoming envelope also reserves 32 KiB once for the sequential candidate/source transfer and 2 KiB per response for adopted witness/index/monitor/receipt metadata, plus existing lifecycle and identity metadata. Outgoing source/control retention is charged to its outgoing reservation. A direct installed-binding caller is count-fenced before allocating lifecycle metadata: traversal stops at the existing normal plus incoming capacities, response count cannot exceed the incoming lane, and its reserved metadata cannot exceed the existing control-byte cap. Mixed normal claims still happen after response entry, so no precheck erases an entered prefix. Logical admitted byte caps do not bound every transient encoding/hash/CAS copy or application-held term.

Legacy mixed arrays enter their response members first, preserving response-member relative order, then attempt normal-member admission under the same original cutoff. Normal relative order and aggregate notification/response omission remain intact. Response recognition is map-only for a batch member; a nested array is one invalid normal member returning `-32600`, never a recursive response prefix. Its normal permit/count and original actor generation are preserved. A response prefix cannot turn a multi-member normal array into one work slot. Already entered responses are not replayed if normal admission later fails. The typed partial outcome reports a known accepted-response count, or `:unconfirmed` when prefix completion could not be observed before cutoff. Normal attempts are capped at 512 and never renew the captured deadline. Response-only 202 is published only after all response loans were considered; 202 does not mean the callback consumed a result or client bytes arrived.
