# Mounted HTTP control, initialization-array, and MRTR slice

This private implementation extends the mounted runtime HTTP gateway. Its captured base is canonical `c1ae91b8132f2fb8b7a73d2bcaf24399860c256a` plus the exact preceding 12-path retained-session overlay (manifest SHA-256 `f52627b2f5e0976473881f7feb592b454c4121b4bb8fed9c128f3ad96f57e4a4`). It does not retire public HTTP APIs or complete the remaining subscription and listener migration.

## Implemented behavior

A notification-only legacy array admits every member before its single charged 202 response. After that socket response returns, the installed Gateway retains the accepted envelope and its original deadline. Later members can continue without reusing the returned socket as authorization. Expiry or Gateway/root death prevents later callback effects; a replacement lifetime cannot adopt old work. Count and input-byte credits remain held until the complete envelope settles.

An initialization array must contain exactly one `initialize`, in its first position, with a string or integer ID. Malformed order or repeated initialization is rejected before creating a claim or invoking callbacks. The first successful initializer establishes one addressed session lease and version; later ordered members share the already initialized runtime handler state. A failed initializer stops following members, terminates its captured session, and suppresses the session header. Modern arrays remain rejected. The final response still requires the existing whole-array output authority, rather than authority from the first member.

Mounted MRTR uses the existing root-addressed replay cache and sealed request-state implementation. Actual wire tests cover an input-required result, a completed retry with the original application request state, and replay rejection before another callback effect. Pure mounted tests also cover endpoint, principal, and tenant changes.

Cancellation notifications use an admitted source permit, a token-only Scheduler message, and an authenticated acknowledgement. The source retains its permit even if the source socket returns or its deadline expires while the Scheduler is paused. The Scheduler rechecks the original source owner, generation, scope, phase, cutoff, and target immediately before mutation. Expired sources only settle their control permit. There is no renewed five-second cancellation budget.

Legacy targets require the same validated session lease and backend epoch. Integer and string IDs remain distinct. `initialize` is protected. Modern targets require a sessionless binding and the same nonempty server-resolved principal, tenant, and endpoint. The identity comes from the existing configured resolver or verified authorization claims; JSON body identity assertions confer no authority. Inbound notification context has era `:unknown`, so the source is correlated through its installed sessionless binding and resolved identity, while the target must be a modern request. An unrelated runtime lifetime cannot be targeted.

Anonymous modern cross-POST cancellation is an advisory no-op. Closing the originating response socket still cancels only that invocation and prevents its callback state commit. Native `Client.send_cancelled/3` already implements modern ordinary-request cancellation by closing that response stream (`Client`'s modern HTTP branch), and this slice preserves that behavior.

## Bounds and adjacent lifecycle repair

There is one cancellation-origin metadata row per admitted envelope. Its bounded metadata and the at-most-4,000-byte request ID are precharged in Gateway ingress; the row is removed when that envelope settles. The metadata reservation charges `4,512 + 2 * external_size({scope, lease, identity})` once, under the existing input byte limit. Per-target mailbox payloads and unbounded cancellation fan-out tasks are not introduced. Existing HTTP writer liabilities remain charged through actual IO completion or monitored socket death.

A separate Admission repair transfers the old unbound monitor to the new output phase during `release_step`, cancels the old timer, and tags new unbound timers with the phase identity. Queued old timers and DOWN messages cannot retire a fresh phase. The regression performs 30 unbound transitions with two held work permits, checks one current monitor throughout, then proves owner-death cleanup and late-message rejection. This corrects an observed stale-monitor teardown crash rather than relaxing a timeout or bound.

## Validator and consumer compatibility evidence

The preserved mounted validator rejects a bare `notifications/cancelled` body with only a modern protocol-version header: status 400, error code -32602, `_meta` missing-required-field data. A standalone in-memory comparison runs the exact frozen pre-convergence HttpPlug source and the candidate against the same installed runtime; both return that identical result. This slice does not loosen request-header or metadata validation. The additional trusted cross-POST extension is qualified using the already accepted metadata-and-header envelope.

The existing anonymous HTTP cancellation consumer (`client/modern_http_request_stream_test.exs`) checks closing its request stream, not correlating an independent anonymous POST. The native Client implementation explicitly takes that stream-close path. The pinned 2026-07-28 `CancelledNotification` schema describes previously issued in-flight work and advisory cessation without introducing an identity field. Local official SDK fixtures and conformance runners contain no cross-POST cancellation assertion. These observations establish baseline client behavior separately from the additional trusted extension; they do not claim a new full SDK conformance run for this slice.

## Remaining full-v2 gates

Individual request cancellation currently looks up the target phase retained by the Scheduler. Running targets are qualified here; explicit queued-target cases and future members still held in a Gateway legacy batch require further coverage. That behavior must be resolved coherently before claiming full batch cancellation support. Modern subscription-listen streams, retained resource publication with its authoritative origin through actual writer acknowledgement, and default/alias HTTP routes remain separate convergence gates. Six deprecated HTTP callables and two wrappers require complete supported replacement consumers before removal. Listener ownership and the native SDK/full canonical suite must be qualified against the combined final source. These gates remain required for v2.
