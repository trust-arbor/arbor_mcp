# MCP requirement evidence

Generated by `python3 scripts/check_mcp_assurance.py --write-docs`.

Use **Remaining library work** below to find known implementation, qualification and
inventory work. **Supported** means the stated library scope has an implementation;
it does not mean every clause in the wider source bundle has an exhaustive test.
External duties and unadopted profiles are separate from library work.

This is a reviewed requirement inventory, not a certification. Links identify assertions configured in CI;
only the checkout-bound CI artifact records that they actually passed. Source inventories
marked partial or pending prevent a claim of complete specification coverage.

## Remaining library work

- **WORK.TASKS_INVENTORY** (inventory): Complete Tasks prose/schema dispositions and register existing lifecycle/client/notification assertions.
  Closure: Every Tasks section/export has a disposition; named server/client lifecycle evidence executes. Bundles: TASKS.TTL, TASKS.HEADERS, TASKS.UNKNOWN, TASKS.INPUT-KEY, TASKS.FAILURE.
- **WORK.EXISTING_EVIDENCE** (qualification): Link existing assertions for bundles with no recorded executable evidence.
  Closure: Every supported bundle has implementation paths and named local or official assertions. Bundles: CC.SECURITY, CORE.ERA, CORE.STDIO_LIFECYCLE, CORE.CANCELLATION, CORE.LOGGING, CORE.AUTH_SECURITY, OAUTH.BEARER, OAUTH.REFRESH14, DCR.RESPONSE.
- **WORK.TOKEN_TYPE** (implementation): Reject a final MCP access-token response whose required token_type is absent.
  Closure: Automatic client-credentials, enterprise and refresh paths reject missing type; generic token-exchange compatibility remains covered. Bundles: CORE.AUTH_TOKEN, RFC6749.RESPONSES.
- **WORK.IDJAG_TYPES** (implementation): Reject malformed primitive identity claims in signed ID-JAGs.
  Closure: Signed non-string required identity and optional scope claims are rejected; valid signed claims still pass. Bundles: EMA.CLAIMS, IDJAG.CLAIMS.

## External responsibilities

Host responsibilities and unadopted profiles are not library test passes.

| Bundle | Owner | Required integration / policy |
|---|---|---|
| CC.AS-METHODS | authorization server | Supporting AS metadata advertises private_key_jwt or client_secret_basic. Metadata helper is configurable; it does not implement a complete token-issuing AS. |
| CC.AS-ALGS | authorization server | An AS supporting JWT authentication publishes signing algorithms. Host must configure and enforce its advertised methods and algorithms. |
| CC.SECURITY | client and host | Host/AS provision confidential credentials, trust, least privilege and secure deployment. |
| EMA.SSO | host | Obtain the initial identity assertion from the configured enterprise IdP. Host owns initial login, SAML validation, registration and administrator policy. |
| EMA.ISSUANCE | IdP and authorization server | Apply enterprise trust policy and issue a token restricted to the authorized MCP resource. The grant helper does not provide token issuance, SAML policy or a complete OAuth AS. |
| EMA.TENANTS | IdP and authorization server | Bind issuer, subject, client and tenant to the appropriate trusted registration. Host registration/policy responsibility; helpers alone do not qualify a multi-tenant AS. |
| CORE.META_NAMES | host/extension author | Use reserved-prefix and key-name rules for metadata/extensions. Trace context values must follow W3C formats when supplied; self-reported identities must not drive authorization. Application/extension authors own custom metadata and trace values; generic map preservation is not validation or authorization. |

## Unadopted profiles

- **IDJAG.OPTIONAL**: When adopting actor delegation, rich authorization, multiple resources or sender-constrained grants, enforce their profile processing and proof-of-possession requirements; never treat a cnf claim as proof. Arbor does not implement DPoP, actor delegation or RAR policy. A host accepting these claims must validate them before access-token issuance; signature helper success does not authorize them.
