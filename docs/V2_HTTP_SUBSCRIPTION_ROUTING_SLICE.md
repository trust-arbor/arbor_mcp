# Mounted modern subscription routing

This slice extends the qualified HTTP listener-lifetime core. A mounted `subscriptions/listen` POST now uses its existing Runtime, installed Gateway, bounded runtime-owned subscription registry, and original entry admission. It does not initialize another handler or connect a singleton protocol peer. Callback publications reach addressed listeners through the same native Mailbox/Delivery retention and the root's borrowed-IO liability budget.

## Authority and lifetimes

The entry captures one potential listener cutoff from the configured root subscription service's `max_lifetime_ms` (default one hour). Only the installed Gateway may establish it while the original scalar RPC admission remains live. Registration succeeds once; its immutable successful output phase permits the established target to outlive the ordinary request cutoff. It never renews callback, service or publication-source authority. The private listener capability contains a nonce distinct from socket PID and wire ID. Registry and Listener operations authenticate that nonce so stale cleanup cannot address a subsequent registration on a reused socket process.

`Subscriptions.publish` in a runtime HTTP callback captures authoritative Admission token, output phase, owner, scope, generation, original cutoff, session lease and trusted identity. The source is checked before queue admission, checkout and physical IO. A pending callback that is cancelled cannot deliver a queued event or commit handler state. A completed callback may deliver an already admitted event only through that original source cutoff. An expired source is discarded and acknowledged; a healthy target listener remains open for subsequent current publications.

Anonymous public callback publications retain fanout under the configured filter/publication authorization within the exact runtime, cohort and private transport endpoint. Anonymous sources cannot satisfy trusted listeners. Trusted sources match principal and tenant, unless existing explicit publication authorization permits the topic for another trusted identity. These publication rules do not change anonymous cross-POST cancellation into an authenticated control operation.

The host router's nonempty `script_name` is the canonical private transport endpoint for every accepted route under one forward. A directly installed Plug uses its configured logical `:path`. Client headers and body metadata cannot select this field. The public `Context.current().endpoint`, MRTR audience and OAuth resource remain the configured logical endpoint. Forward roots and relative logical URLs share their lease domain; different forward prefixes on the same Root cannot share cancellation, publication or session/replay authority. Addressed standalone session calls that omit this private metadata retain their trusted inspection contract. Explicit malformed private metadata fails closed.

Filter authorization or registry-capacity rejection after provisional establishment can return only to the original scalar error-response proof while setup is live and unattached. The installed Gateway rechecks the same reservation token, phase, scope, owner, generation and cutoff. Establishment stays spent; no listener or deadline is renewed. The client gets a fixed charged error, and setup accounting settles after its real response receipt rather than waiting for the long listener lifetime.

## Physical IO and bounded retention

The socket owner sends headers and chunks itself. Registry admission charges each actual write before handing it to the borrowed adapter. Mailbox/Delivery loans stay charged until an actual physical write returns, or until a proof rejects the event before IO starts. Token-only ready messages contain no event payload. One entered write is allowed per writer; logical expiry, generation replacement or root stop cannot kill that borrowed process or reuse its unresolved IO credits.

Active listener count/metadata use the existing `max_http_writers` and `max_http_writer_metadata_bytes` aggregate limits. Header, acknowledgment, event, comment and completion writes use `max_http_io_frames`, `max_http_io_bytes` and `max_http_io_frame_bytes`. Root-owned subscriptions additionally retain their existing `max_global`, per-principal/tenant, per-listener queue and message/queue byte limits. Those are distinct bounded pools; this slice does not claim a single runtime output-byte limit bounds their sum or all host/producer memory. Whole admitted writer-row CAS publication can temporarily copy that bounded row, and retains the existing finite attempt/control budget.

At listener expiry the registry preserves a separate finite completion-only tail captured at establishment: listener cutoff plus configured output timeout. Only the attached Listener can authorize it, and only the socket can consume its single-use receipt. The registry constructs the fixed `notifications/subscriptions/complete` frame from the validated stored wire ID. No callback payload, success publication, service call or ordinary work can use this tail. Maintenance before authorization or between authorization and preparation cannot erase it; duplicate, stale-generation and expired receipts fail. Completion loans and IO credit release after actual ACK.

## Private seams

`HTTPListenerBinding.validate/1,2` keeps the writer domain opaque. `HTTPWriterRegistry.establish_listener/3`, `attach_listener/4`, `listener_setup/1`, `listener_wait_deadline/2`, `authorize_listener_completion/1` and `prepare_listener_completion/1` authenticate installed actors and retained rows. `Subscriptions.listen_http/4` and the Listener's `checkout_http/4`, `delivered_http/3` and `cancel_http/3` are internal addressed routes. `RuntimeSubscriptionStream` uses the actual Plug writer and distinguishes a rejected pre-IO source from a real IO failure; only the former can preserve a healthy target.

For runtime mounts, handler initialization uses `Runtime.handler_args` once. A static/fn/MFA `handler_opts` result is charged per-request context available at `Context.current().application_context`, subject to the original entry cutoff. Moving a request-derived init option therefore means reading that context inside the callback rather than rebuilding handler state for each POST.

## Qualification and remaining convergence

Qualification is recorded against exact source hashes in the immutable handoff manifest. The standalone selection covers the installed writer/core plus modern routing, completion-tail races, held borrowed IO, stale-source target survival and mount/session metadata. The physical selection uses real Cowboy on random loopback sockets, two actual Router forwards on one Runtime and the retained native Client literal `subscriptions/listen` API. It covers public fanout, mixed trusted/anonymous isolation, same-principal cross-forward cancellation isolation, Client receive/cancel, and cross-forward legacy lease/replay rejection. No repository test helper, global port cleanup or shared dependency build is used.

The exact source passes 63 standalone core/installation/registry/routing cases on Elixir 1.17.3/OTP 27.0.1, 1.19.5/OTP 28.4.1 and 1.20.3/OTP 29.0.5. A separate 42-case retained subscription/Mailbox/Origin/Handler selection passes both supported toolchains. The seven actual HTTP cases pass on both supported toolchains, including bounded filter-denial and listener-capacity error responses with prompt setup accounting settlement. All three compile with warnings as errors and pass full formatting. Current strict Credo runs 64 checks across 735 files without issues; ExDoc succeeds. Unchanged normal Dialyzer reports 72 current and 66 minimum filtered warnings; direct unfiltered audits report those same totals and zero warnings in all fourteen owned production modules. No new warning filters or suppressions were added.

This slice does not yet implement the retained 2024 `/sse` handshake and `/message` delivery aliases, addressed legacy resource-update publication, reverse HTTP server helpers or removal of `HttpPlug.start_link/0,1`. Those remain explicit full-v2 gates. Modern POST subscription behavior and private mount-domain isolation do not qualify those legacy routes merely because a guarded error response exists. Actual Phoenix archive consumers and the complete combined application/SDK suites remain integration gates after the parent merges this source union.
