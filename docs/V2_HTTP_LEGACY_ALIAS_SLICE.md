# Runtime-backed legacy HTTP aliases

This slice activates the retained deprecated HTTP+SSE transport on the existing mounted runtime. An enabled GET `/sse` creates or addresses a session without initializing a new handler, announces its `/message?sessionId=...` URI, and establishes one immutable replay/IO target. The original request cutoff still governs authentication, setup, initialization claims and publication. The target's longer cutoff is the earlier of the original entry plus the configured session TTL and the actual captured lease expiry. Subsequent session activity does not extend that target.

The POST alias uses the same root Scheduler, handler state, era/authentication/body/origin validators and session initialization claims as the MCP endpoint. It rejects conflicting query/header identities and modern envelopes on the deprecated transport. Recognized disabled aliases return 404; an explicitly configured primary `/message` endpoint and the established mount-root POST behavior take normal MCP precedence even with aliases enabled. Modern GET/DELETE on recognized session routes return 405 before setup. The alias handshake runs only for GET; DELETE retains the mounted addressed-session deletion guards. A legacy POST alias must differ from the primary endpoint and mount root. Conflicting configurations reject the GET handshake with a fixed configuration error before session setup, while ordinary primary POST remains valid. A forwarded mount has one private transport domain across its MCP endpoint and aliases; a different forward cannot reuse its lease or cursor.

An ordinary response reserves its prospective complete replay event before handler state can commit. The installed Controller receives the exact prepared event companion before the worker exits. The original socket finalizes and durably publishes that companion before returning empty HTTP 202. The SSE target independently reads the detached retained event and charges each physical chunk through actual adapter return. Reconnect uses Last-Event-ID without repeating callbacks. A legacy array publishes one complete ordered event, omits notifications, retains invalid-member responses, and cannot publish an earlier successful member as a failed aggregate. Earlier committed state remains when a later member fails.

A server-authored terminal failure without an event companion returns one charged fixed HTTP 500 response. It cannot claim durable-event-before-202, retry a callback, renew authority or fabricate a replay event. A notification-only array keeps its accepted work semantics and creates no response event. Visible plus pending replay saturation rejects the proposal before state commit.

Guardian maintenance now preserves an explicitly retired writer row as retired. Previously, a live failure tail could resurrect the row after physical IO returned and socket retirement, leaving no frame but blocking reuse of the same PID until the tail expired. A paused-Guardian regression preserves the failing baseline and verifies that actual return plus retirement reclaims the row, with no early release of unresolved IO.

Qualification uses independently copied dependency/native sources and build domains. The isolated selection contains 17 new Plug/pure-process cases and 60 combined alias, replay, output, session-target and modern-listener cases. Actual random-loopback Cowboy cases cover the literal 2024 protocol, endpoint handshake, durable replies before 202, live delivery beyond the short RPC cutoff, immutable stream expiry despite session renewal, reconnect replay, cross-forward rejection, arrays, failed aggregates, saturation, addressed DELETE, configured primary path collisions and modern method fences. Final supported-toolchain counts and compiler/static logs are recorded in the immutable handoff manifest. No repository test helper or global port cleanup is used.

This is a narrow transport slice. Resource subscription publication, progress/reverse controls on retained streams, public HTTP callable retirement, final Phoenix/archive consumers and continuous transport soak remain release gates. The session target is not callback, request or publication authority. ETS replay durability is retained-runtime durability; this slice makes no disk or root-restart durability promise.
