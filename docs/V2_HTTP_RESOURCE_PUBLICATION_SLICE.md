# Addressed HTTP resource publication

The mounted runtime now records successful legacy `resources/subscribe` and `resources/unsubscribe` callbacks in its addressed resource service, using the actual session epoch. The callback's original Task, invocation token, output phase, runtime generation and cutoff remain authoritative through the final store mutation. A failed registration returns a fixed protocol error and keeps the previous handler state. Native Test/BEAM callbacks retain their existing application-owned resource behavior.

`Server.notify_resource_update(uri)` and `HttpPlug.broadcast_resource_update(uri)` remain exported. Inside an actual HTTP callback they publish a fixed `notifications/resources/updated` event to eligible addressed subscriptions. Outside that callback they return `{:error, :no_request_context}`; there is no global registry fallback. URIs must be nonempty UTF-8 binaries no larger than 4,096 bytes. Successful lookup is bounded by the resource service's page count and byte limits. `:lookup_page_required` rejects before any replay append.

Targets must share the source's runtime, private forwarded endpoint, principal and tenant, and each target lease must remain current at its final session-store mutation. Anonymous private-resource publication does not satisfy a trusted subscription. An accepted target snapshot can race a later unsubscribe; unsubscribe does not roll back a publication already accepted from that snapshot. Session deletion or epoch replacement rejects old leases. A new session using the same wire ID does not inherit its old URI registrations or replay events.

Each successful append is durable within the configured retained session store before downstream delivery. The existing replay count and byte limits account pending response candidates together with visible events. An error after an earlier target append returns `{:error, {:resource_publication_partial, reason, counts}}`, where counts include `subscribers`, `stored` and `delivered`. Earlier appends remain committed; the library does not retry the callback or undo accepted replay. Automatic tracking and explicit publication are callback service effects, not a transaction with later handler-state/output preparation. Cancellation that wins the final store authority check prevents tracking. If registration or removal is already accepted and cancellation then wins Scheduler commit, the addressed change remains while the proposed handler state is discarded; the original RPC reports the existing typed `request_cancelled` error. The library does not report cancellation as rollback of an entered service effect. This also applies when callback output validation fails after a successful store mutation.

The retained success shape is `%{subscribers: eligible_count, delivered: live_accepted_count}`. As in the earlier asynchronous SSE implementation, `delivered` records acceptance for a currently live stream after its durable append. It is not a client-byte acknowledgement. Actual GET chunks continue to use the existing writer ticket and remain charged until physical IO returns or the monitored writer dies. No additional receipt registry or socket payload mailbox is introduced. A GET disconnect preserves registrations and replay; reconnect reads the same committed event. Unsubscribe prevents later lookups, while DELETE/TTL retires the exact session epoch.

HTTP producer authentication now covers JSON replies, legacy SSE replies and accepted HTTP notifications. Scheduler publishes one existing precharged, payload-free protected metadata row per actual HTTP Task before allowing its callback to run; it removes the row on completion, death and phase replacement. The row remains at most 512 bytes and is already covered by HTTP ingress metadata admission. Store checks read that protected table directly. They never synchronously call Scheduler, so callback service operations do not create a Store→Scheduler wait cycle. Copied proofs, foreign callers, expired Tasks and old session epochs cannot acquire new publication authority.

Modern JSON callbacks and accepted id-less `tools/call` notifications can publish as application effects without creating a session or returning a session header. The modern protocol's URI notification subscription is `subscriptions/listen`; this slice does not restore the removed modern `resources/subscribe` RPC or invent a modern session. Existing modern public-topic publication keeps its separate authorization policy.

Qualification uses independent dependency/native source copies and per-toolchain build domains, with standalone ExUnit harnesses and no repository test helper or global port cleanup. The new pure cases cover registration, offline replay, all HTTP Task producer variants, foreign and expired authority, native callback compatibility, cancellation, session replacement, private endpoint/principal/tenant isolation, capacity failure and explicit partial outcomes. Three real random-loopback Cowboy cases cover live resource updates beyond the short RPC cutoff, GET-gap replay/unsubscribe/DELETE and private cross-mount/trusted-to-anonymous isolation. Each owned listener is monitored DOWN and its socket refuses connections after cleanup. Exact final counts, runner commands and quality receipts belong to the immutable handoff manifest.

This slice retires no public callable. Progress/reverse helpers on retained streams, final combined canonical/consumer qualification and continuous HTTP soak remain release gates. Publication acceptance does not restore an expired request, phase, lease or borrowed socket's IO authority.
