# Private runtime output ledger prerequisite

This prerequisite is included in the MCP v2 draft and adds three private modules under `Arbor.MCP.Server.Runtime`: `OutputCodec`, opaque `OutputTicket`, and `OutputLedger`. It is not wired to `Config`, `Scheduler`, `HandlerServer`, stdio, HTTP, notifications, or batches. Existing protocol output paths and consumers therefore do not yet gain these bounds. Inclusion of the private source is a checkpoint for review and qualification, rather than production output convergence.

## Prepared output and ownership

`OutputCodec.prepare(term, opts \\ [])` accepts plain JSON maps/lists, strings, numbers, booleans, and nil; atom map keys are allowed. It rejects structs, custom encoders, ambiguous atom/string keys, unsupported values, and invalid UTF-8. Integration must normalize Content/Result structs into canonical protocol values before this boundary. Custom `Server.call` replies may contain non-JSON terms and require their own explicitly bounded serialized-term channel; blind JSON conversion would break that contract. The original term is checked before encoding; JSON frame bytes are checked afterward. The frame limit **includes one LF**; charged wire bytes include that same delimiter. Returned `wire` is the encoded JSON body, so a stdio writer appends exactly that one reserved LF.

`OutputLedger.start_link(owner: local_lifetime_pid, generation: ref, ...)` starts the actor. `OutputLedger.ref(pid)` returns its opaque reference. Defaults are `max_frame_bytes: 1_048_576`, `max_output_bytes: 4_194_304`, `max_output_frames: 128`, `max_scope_bytes: 65_536`, and `call_timeout_ms: 5_000`. Limits must be positive; the metadata limit must also accommodate its reserved initial control slot.

| Operation | Contract |
| --- | --- |
| `open_scope(ref, fresh_scope)` | Only the lifetime owner can register a scope. Use a fresh opaque runtime scope reference for each connection; never reopen a retired identity. Hidden preparation is possible before consumer subscription. |
| `prepare(ref, term, scope: scope, owner: local_runtime_pid, deadline: absolute_monotonic_ms)` | Returns `{:ok, ticket}` or an explicit error. Scope is required, must already be open, is individually capped at 4 KiB serialized, and should be an opaque runtime scope reference. Unknown/retired scopes fail without allocation. The future deadline must fit a signed 64-bit integer. The supplied owner defaults to the lifetime owner. Producer leases retain hidden prepared output. |
| `publish(ticket)` | Only the ticket's runtime owner can publish. Publication moves the lease from producer to owner and makes the output visible. Producer death after publication does not discard it; the former producer loses release authority. |
| `release(ticket)` | The producer may abandon hidden output; the runtime owner may release any stage. Repeated release of an already released ticket is harmless. |
| `subscribe(ref, scope, consumer)` | Only the lifetime owner may register one live local consumer per already-open scope. Consumer death retires the scope. |
| `checkout(ref, scope)` | Only the registered consumer may obtain `{:ok, ticket, term, wire}`. Returns `:empty` for a live empty scope. At most one frame per scope remains in flight. |
| `ack(ticket)` | Only that in-flight consumer can release its credit. Repeated ACK after release is harmless. Integration must ACK after the actual bounded writer operation has settled, not merely after forwarding into another mailbox. |
| `begin_drain(ref, scope, absolute_deadline)` | Stops new preparations but allows already prepared tickets to publish before the drain deadline. Expiry explicitly closes the scope with `:drain_timeout`. |
| `seal(ref, scope)` | Drops hidden candidate/prepared output and prevents publication. Previously queued or delivered frames can drain; an established drain deadline still applies after sealing. |
| `retire_scope(ref, scope, reason_atom \\ :connection_closed)` | Reason atoms are capped at 64 serialized bytes. Atomically abandons all owned output for the scope, emits one terminal event, and removes its metadata. Unknown-scope retirement is an idempotent no-op. Late producers cannot recreate a missing scope; only explicit owner registration can do that. |
| `reset_generation(ref, fresh_ref)` | Retires the old generation and returns `{:ok, fresh_ledger_ref}`. Old references/tickets fail; all scopes/credits/monitors are reset. Reusing the same generation is rejected. |
| `drained?(ref, scope)` | Reports whether this ledger holds any claim for the scope. This does not prove input callbacks have settled or a transport has flushed. |
| `stats(ref)` | Returns stage counts, charged output bytes, reserved metadata bytes, scope count, pending control count, and generation; contains no payload. |

All CAS operations have one fixed absolute deadline and at most 512 contention retries; exhausted retries return `:output_contention`. Preparation CAS checks the original output deadline, and control admission, actor waiting, and mutation CAS share one finite absolute call budget. Confirmation and publication are capped by the original output deadline as well as `call_timeout_ms`; ACK/release use a separate finite cleanup budget. All control operations have caller-side absolute acceptance deadlines. A timed-out control cannot later dequeue a frame or register a subscriber. Its occupied control slot remains bounded until the actor handles/reaps it. Prepared confirmation that becomes uncertain is expired and reaped with its monitor. Lifetime owner death stops the actor and deletes its ETS payloads.

Consumer events contain identity/control data only:

```elixir
{:arbor_mcp_output, generation, scope, :ready}
{:arbor_mcp_output, generation, scope, {:closed, reason_atom}}
```

Ready wakes are coalesced. A checkout attempted while previous delivery is still in flight resets the consumed wake; subsequent ACK emits another wake if queued frames remain. Expired published frames close the scope explicitly instead of disappearing silently. Consumer code must validate generation/scope and discard any local retained payload after retirement.

## Admission and observed bounds

A single ETS compare-and-swap row owns claims, scope/control metadata, and admitted payloads. A producer charges a candidate's original term, encoded wire/LF, and maximal ticket metadata before ETS retains that payload. The second atomic update publishes prepared data into that same claim; retirement/generation replacement cannot leave a later orphan payload insertion. One count/byte budget covers candidate, prepared, queued, and in-flight stages. JSON frame order follows the owner's publication order.

A separate reserved metadata budget includes scope records, subscriber PID/monitor/control shape, and bounded pending control records. Scope count is capped by `max_output_frames`; pending controls are capped by `2 * max_output_frames + 1` and by metadata bytes. Actor calls carry only `{:operation, opaque_reference}`; request data stays in admitted ETS control slots. Scope admission reserves enough space for at least one seal/retirement operation even at an otherwise exact metadata cap. Only `open_scope` creates scope records. Retirement removes them, so sequential connection churn recycles capacity without tombstones or a generation reset; active concurrent scope capacity exhaustion is explicit. Late producers cannot implicitly reopen retired scopes, and the trusted lifetime owner must use fresh scope identities.

These are bounds on retained, charged ledger data. They are not a byte-for-byte BEAM allocator/RSS ceiling: ETS/CAS snapshots, temporary encoding allocation, actor replies, VM bookkeeping, and callback-owned terms have separate costs. A caller may already hold arbitrary output before invoking this API. The whole-row CAS deliberately favors atomic retirement over avoiding transient snapshots; integration/performance qualification must measure that cost. Direct arbitrary sends/ETS mutation bypass this private API and are outside its admission contract. Token-only control records are bounded; this slice does not prove a hard bound on raw actor/consumer mailboxes across arbitrarily delayed caller publication or unconsumed notifications over repeated generations. Integration must retain controlled producers, generation-aware consumers, and lifetime supervision, and pressure qualification must examine those queues.

## Integration order and EOF rule

1. Add runtime-owned limits/lifetime supervision and retain the ledger reference inside the runtime. Explicitly open its fresh connection scope and retire it on scope replacement; owner registration is the authority boundary, so do not reuse retired scope identities.
2. Have result dispatch normalize protocol output and prepare its ticket before committing accepted callback state. On failure, choose the existing explicit overload/error policy. Validate active generation/scope/deadline at the commit boundary, then publish the reserved ticket; abandon it on stale completion.
3. First fix work admission so **each legacy batch member consumes work capacity**: the current Test/BEAM candidate counts a whole batch envelope as one item, which leaves an explicit release gap against the accepted runtime contract. Reserve per-member work counts/bytes or reject a batch before callbacks when that capacity is unavailable, preserving member order and notification omission. Then add batch aggregation so modern rejection and legacy grouped replies prepare one final wire frame; retain/release existing held input claims until aggregation settles. This slice does not implement aggregation.
4. Route every response, error, notification, subscription event, and control output through this same ledger before removing legacy output paths.
5. Add a runtime-owned writer that checks scope/generation/deadline, holds one delivery credit through actual IO, ACKs afterward, and closes honestly on write/cleanup failure.
6. **Clean stdin EOF seals input admission only. Already accepted callbacks must still be able to prepare their replies under the original scope/drain deadline. Begin output drain only after those invocations have settled/prepared; seal only when hidden output may safely be abandoned.** Closing output preparation at EOF would discard replies to piped requests. Combine input-settled and ledger-drained conditions, with finite explicit drain expiry.

HTTP session/store scope changes, runtime stdio reader/writer ownership, batch completion, transport flushing, and pressure across all production producers remain integration gates. No library-level global Logger mutation is introduced here.

## Qualification

The standalone qualification compiled only these three modules with an independently copied Jason dependency: **39 tests passed** on Elixir 1.17.3/OTP 27.0.1, Elixir 1.19.5/OTP 28.4.1, and Elixir 1.20.3/OTP 29.0.5. Each toolchain passed forced compilation with warnings treated as errors; minimum-toolchain formatting passed. Those results establish the private API behavior, rather than full application integration or throughput.

The same source and focused tests are now included in the full MCP v2 draft at `lib/arbor_mcp/runtime/output_{codec,ticket,ledger}.ex` and `test/arbor_mcp/runtime/output_slice/`. Focused cases exercise concurrent count admission with 80 producers and a suspended actor, byte pressure with 60 producers, atomic retirement with 100 producers, producer handoff and death during confirmation, timed-out checkout preservation, strict consumer credit/wake recovery, metadata-cap retirement, generation reset, 350 sequential retired connection scopes with an unaffected active scope, late producers after scope churn, paused metadata pressure, original-deadline confirmation/publication waits, and explicit deadline/drain/owner cleanup.

Full application qualification used independent copied dependency sources, immutable shared RPC source at `b46cbfe8ced0d29519462f8a83b64e5750caaa92`, and separate current/minimum builds. The final focused suite passed **39 tests** in the full package on Elixir 1.19.5/OTP 28.4.1 and Elixir 1.17.3/OTP 27.0.1. Both toolchains passed warnings-as-errors compilation and full formatting. The exact final private modules also passed the standalone **39 tests**, forced warnings-as-errors compilation, and owned-file formatting on Elixir 1.20.3/OTP 29.0.5. The newest result covers this slice, not the full application.

The current-toolchain application selection matches the local counterpart of CI coverage: `mix test --include compliance --include integration --include requires_http --include requires_stdio --include requires_beam --include requires_bypass`. It passed **20 doctests, 34 properties, and 3,860 tests with zero failures (82 excluded)**. Existing excluded external/interop/performance categories remain separate gates. Current full formatting, strict Credo, warnings-as-errors compilation, ExDoc, and Dialyzer passed with the repository's existing configuration and no new filters.

The test-environment Dialyzer run reports 73 existing filtered warnings. An additional unfiltered audit compared the final candidate against clean committed source at `6ec3d81ab62cae22bed0cba4da1a8cde7f98613f` using identical independent dependency versions, toolchain, test environment, warning options, and qualified PLT, with separate builds. Both returned exactly the same 73 raw warning terms: 35 in library code and 38 in compiled test/compliance support. None referenced `OutputCodec`, `OutputTicket`, or `OutputLedger`. The earlier dev-environment count of 35 omits that test support. This demonstrates no warning delta for this slice; it does not remove the existing warning debt.

Production Scheduler/Config/writer integration, per-member batch work admission, aggregate batch output accounting, custom-call serialized-term replies, input-first EOF settlement, and same-runner throughput/mailbox pressure remain explicit release prerequisites. Successful package qualification alone does not establish those unfinished bounds.
